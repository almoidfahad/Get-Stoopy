# Checkout total readiness boundary

The current quote API returns a product subtotal only: `deliveryFeeMinor` and `totalMinor` are null and `paymentStatus` is `NOT_IMPLEMENTED`. Recipient address, delivery charge, taxes, a final payable total and the customer payment/order workflow are not ready. Previously the storefront inferred that delivery and total were calculated whenever both fields happened to be non-null, and inferred payment was implemented from any other status string. That could make an unexpected or future partial response appear more complete than it is.

The current quote-only storefront now treats non-null delivery/total fields or another payment status as unsupported. It warns, withholds the summary subtotal when this warning is present, does not claim that a final amount or payment is implemented, and retains the ability to release reserved stock. This is a fail-closed presentation boundary, not a final-total calculator. A future implementation must explicitly introduce and validate an agreed complete pricing/tax contract, backend authorization and payment workflow rather than toggling these flags from response shape alone.

Unit and component tests cover numeric, malformed and partial unexpected fields, unsupported payment statuses, and preservation of the release control. Integration coverage checks the current null/not-implemented API contract for create, replay, read, release and release replay. No live fee or tax values are invented; COD checkout, SMS and live payment remain unavailable. No hosted database change or deployment is included.
