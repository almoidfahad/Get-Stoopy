# Vendor inventory workspace

`/vendor/inventory`, linked from the vendor dashboard, provides a responsive inventory layout with an explicitly unavailable records panel and a local stock calculator. The calculator uses the browser-safe core `availableToPromise` rule: on-hand minus reserved. Inputs must be whole nonnegative quantities within the existing inventory maximum; reserved cannot exceed on-hand. It starts blank, does not pretend records are empty, and does not show fabricated counts or low-stock alerts.

This public layout reads no actual inventory and grants no vendor permissions. Its calculator operates solely on transient user input; it does not fetch, save or adjust stock, make reservations, validate a real store, or make a customer availability promise. Navigation/reload discards entries. No actual stock controls, records, variant selector or movement history are connected. Real inventory functions require backend authorization for the selected store/variant, CSRF, input validation, optimistic version checks, idempotency, and careful handling of reservations and movement history. Never treat the local calculation as authoritative.

Tests cover pure calculation boundaries, unavailable layout and DOM interactions for both the calculator and the prior product layout preview using jsdom. These do not verify a real browser, visual fidelity, assistive technology, actual inventory or backend authorization. A separate inventory screen was not supplied in the design references; this interpretation awaits review. No production deployment, payment or database configuration is changed.
