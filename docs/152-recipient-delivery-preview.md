# Pre-order recipient and destination preview

Adds a backend-only, authenticated `POST /api/v1/commerce/carts/:cartId/delivery-preview` with origin/CSRF protection and `Cache-Control: no-store`. It accepts the cart version, recipient name, international phone, address, selected service-zone/boundary IDs and destination coordinates. It checks the buyer owns the cart; validates trimmed contact/address and country calling code; checks the zone is active, the approved boundary is effective and covers the supplied point, the zone is in the cart country, and every cart store has approved coverage in that exact zone and is otherwise serviceable. It uses a repeatable-read snapshot. The buyer's GPS is not required.

The response is explicitly `PREVIEW_ONLY`: it identifies the cart version, city and zone/boundary, with `recipientSaved: false`, `stockReserved: false`, `orderAvailable: false`, and null delivery fee and total. Contact details, address and coordinates are not echoed or written by this application path. The PostGIS query receives the coordinates as parameters. There is no reservation, quote, order, audit or outbox write. As of docs/160, application request logs use registered route templates rather than raw URL paths or query strings; production proxies, database logging/tracing and infrastructure must be separately configured and reviewed to avoid recording sensitive input. Transport security and retention must be reviewed before real customer data is used.

This is a point-in-time validation preview only. It is **not** bound to a subsequent quote or order, does not save or verify a phone, does not validate postal deliverability, item sellability, current stock, pickup/hours/rider availability, routing or delivery price, and cannot guarantee coverage after the read. As of docs/156, it fails closed if multiple approved effective boundaries exist; it does not choose a latest version or implement the designed active pointer. The API accepts zone/boundary IDs; customer discovery, UI, privacy/retention and an encrypted, buyer-owned persistent pre-order recipient/destination snapshot are still required. Authoritative quote creation must later recheck and bind that snapshot, pricing, tax and stock transactionally before enabling checkout/COD. There is no live deployment or database migration in this increment.

Integration tests exercise authentication, CSRF, buyer ownership, stale cart, malformed contact/address/coordinates, out-of-zone or invalid/future/unapproved boundary, partial store coverage, boundary edge, non-echo and absence of reservation/quote/audit/outbox writes on a disposable PostGIS database. No real data is used.
