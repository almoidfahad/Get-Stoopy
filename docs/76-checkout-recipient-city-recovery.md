# Checkout recipient-city and quote recovery UI

Checkout now describes the selected city as the recipient's destination whether a delivery is intended for the buyer or someone else. It clearly states that only a city is used for a stock-reservation quote and that recipient details, addresses and order placement are not yet available. It does not introduce a fictitious buyer/recipient selector, store personal data, request GPS, promise cross-city service or enable payments. Serviceability still checks the backend's existing store/city rules; remote-recipient checkout is not complete.

A recovered `RESERVED` quote now displays its actual destination in the disabled city selector, even when adopted after a refresh. If the current city list cannot resolve that city (including when the list is unavailable or truncated), it says city details are unavailable instead of showing a blank selection or substituting another city. The quote also shows the known city name when available. Expired quotes whose server state is already `EXPIRED` no longer ask the buyer to release stock that is not held; expired-but-still-`RESERVED` quotes retain the release instruction and control. Destination error copy now correctly says **one or more** stores may be unable to serve the city instead of claiming that no store can.

jsdom tests exercise city selection and request payload, recovered quotes, missing city, refresh adoption, stale-version resistance and both expired states. These tests mock the API and router. They do not verify real-browser visuals or assistive technology, real reservation concurrency, payment, address capture, live serviceability or end-to-end remote ordering. This increment does not change backend authorization, database configuration or production deployment.
