# Commerce and workspace recovery UX

This is an incremental UX improvement, not full marketplace UI/UX signoff. Cart and checkout now provide a full-page retry for temporary cart and city-service failures. If an existing reserved quote cannot be loaded, the checkout notice retains the warning that stock may still be held and offers a reload; it does not create, release or replace a quote automatically. Sign-in, unconfigured and empty states do not offer that retry. Customer-facing unconfigured text no longer describes deployment configuration. Account, vendor, rider and admin transient-error retry links now perform a page reload rather than client-side navigation to the current URL. Long unbroken product, store and account details can wrap on narrow screens.

Server-rendered tests cover transient versus signed-out/unconfigured/empty states, existing-quote recovery and each workspace retry destination. Typecheck, web production build and 527 unit/component tests passed. With a **synthetic local API and session**, headless Chromium exercised the cart, checkout, account and workspace retry links using the keyboard; checked unavailable-city and unavailable-reserved-quote recovery; and checked long cart/quote titles for overflow at 320, 390 and 1440 pixels. Axe reported no violations in those specific tested states. No reservation mutation, real identity service or live backend was used in this browser check. This is not a full cross-browser, screen-reader, real-device or accessibility audit.

Payments, ordering, address persistence and many vendor, rider and admin tools remain unavailable; the existing uncertain-reservation warning and retry behavior are unchanged. No database, configuration or production deployment was changed.
