# Product price and cart-entry accuracy

The product card and detail page no longer assume BDT when a catalog currency is missing or malformed. They show “Price unavailable” instead. A positive, parseable price and usable currency are required for an in-stock option to appear in the add-to-cart selector; stock status remains distinct from price availability. The backend remains authoritative for catalog, price, currency, stock and cart validation. No currency or price is invented.

The product quantity field keeps invalid input visible and blocks submission with an associated error rather than silently reverting the value to one. A selected option that disappears on refresh requires an explicit new selection, avoiding accidental substitution. Option and quantity controls are disabled during a mutation, repeated in-flight requests from the same control are guarded, and success feedback clears after an edit. A network or server failure now suggests checking the cart before retrying because an uncertain response does not prove that a request was not applied. Existing version-conflict handling still refreshes without automatically retrying an update.

DOM tests use mocked network/router responses and cover quantity boundaries, chosen option and payload, option disappearance, pending state, ambiguous failure and cart version conflict. Server-rendered tests cover missing/invalid currencies and unavailable prices. These are not real-browser or assistive-technology reviews, nor live stock/cart tests. The Vercel preview is unconfigured and cannot show the populated product workflow. No database configuration, backend authorization or production deployment was changed.
