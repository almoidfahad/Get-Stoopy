# Admin dashboard UI foundation

This first admin dashboard increment is a responsive **layout only** at `/admin`, inspired by `references/file_000000001458821082c41adcad8398e0.png`: dark sidebar, workspace header, overview cards and sales, orders, geography, categories and health panels. The screenshot's example identities, metrics, charts, geographic counts, operational status, support claims and quick actions are not presented as real data. Module labels are non-interactive rather than links to missing workflows. This is not a complete admin portal or an approved pixel match.

The page only reads the existing `/auth/me` endpoint to distinguish a signed-out session, a session that exists, and an unavailable response. **It does not check or grant admin permissions or geographic scope.** The static layout and unavailable placeholders can be seen without a session because they contain no privileged data. The session's IDs, scopes and CSRF token are never rendered. Every future admin query, metric and action must independently enforce backend permission, scope, step-up and data-minimization requirements; frontend presentation cannot provide authorization. No actual dashboards, scoped records, system health, finance, account management or admin actions are connected.

Server-rendered tests cover session states, malformed responses, unavailable panels, missing feature links and absence of sensitive fields. They mock the session endpoint and do not validate real authentication, scope enforcement, geographic isolation, browser interaction, mobile visuals or accessibility. Vercel preview has no backend configuration and should show the access-unavailable state. Full vendor, rider and scoped admin workflows, real data integration and visual review remain open.
