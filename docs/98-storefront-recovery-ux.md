# Storefront recovery UX

This is an incremental UI improvement, not full marketplace UI/UX signoff. Missing routes now use a branded recovery page, and missing products have their own explanation and links to the shop and home. A route error boundary provides a retry button without exposing exception details. The home collection differentiates an unavailable service, an unconfigured market and an empty published collection. Shop and product unavailable states use normal page reloads for retry; the shop preserves applied filters. Customer-facing copy no longer exposes the shop configuration variable. Search forms show an outer focus ring so the input outline is not clipped.

Component tests cover the recovery actions and safe error text, and server-rendered tests cover catalog state copy and the filtered retry URL. On a locally built server with an unconfigured API and a synthetic market identifier, headless Chromium checked both missing routes returned HTTP 404, no horizontal overflow, Axe results, skip link, search focus ring and the shop reload at 320, 390 and 1440 pixels. This is not a screen-reader, real-device, cross-browser or complete accessibility audit; the route error retry was tested at component level, not through a live backend exception. No real market, data, login, checkout or portal operations were tested.

Real catalog and authenticated services still need configuration and end-to-end verification. Payment/order placement, address persistence and many vendor, rider and admin workflows are not operational. Production was not changed by this work.
