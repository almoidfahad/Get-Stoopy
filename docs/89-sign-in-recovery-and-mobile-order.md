# Sign-in recovery and mobile-first order

The login page puts its primary action first in the DOM and on mobile; desktop keeps the image on the left. It offers a route back to shopping and distinguishes an unavailable sign-in start from a failed identity-provider callback without displaying internal errors. If configuration, provider discovery or transaction-cookie creation fails, the existing sign-in-start route returns a non-cacheable relative redirect to the recovery message instead of an opaque server error. The successful provider redirect and cookie flow are unchanged; the relative path avoids deriving a redirect origin from the request host. This does not alter authentication, authorize a user, or create a fallback login.

Automated tests cover the successful handoff and configuration/provider/cookie failures with mocked dependencies; a real identity service, login, registration, password recovery, assistive technology and device coverage remain unverified. Account registration, social providers and credential forms belong to the configured identity service; this page does not advertise unsupported capabilities. Design fidelity still requires review. No database or production configuration was changed.
