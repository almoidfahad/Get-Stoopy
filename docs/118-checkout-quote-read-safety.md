# Checkout quote-read recovery

The checkout previously trusted the response when loading an existing active quote. After a release version conflict, it also claimed the page was refreshed even if reading the newer quote failed or returned unrelated, older or malformed data. Either path could render a broken panel or present stale stock information as current.

The existing browser-safe quote-shape check is now shared between the server-rendered checkout page and the client. A recovered active quote must have the fields used by the panel and match the cart's active quote and cart identifiers. Otherwise the page shows the existing reserved-quote-unavailable notice and reload link without inventing a new reservation. After a release conflict, the panel adopts a readable matching quote only if its version is newer than the version that conflicted and newer than the latest quote already displayed. When recovery fails, the last known status is labelled as such, definitive hold claims and further checkout actions are suppressed, and a full reload is offered. Successful recovery reports the latest available details rather than claiming a page refresh. A delayed older release response also cannot overwrite a newer quote already displayed.

Local verification: 650 unit/component tests, typecheck and isolated production web build passed. Tests cover missing fields, wrong identifiers, unsupported state, malformed items, unreadable and stale conflict reads, newer valid reads, a newer quote arriving during a delayed response, and focus handling. Chromium with a synthetic checkout fixture at 320, 390 and 1440 CSS pixels checked malformed server-rendered recovery, conflict with unreadable quote, last-known status, keyboard focus/reload, selected Axe scans and document overflow. No real checkout or identity service was used.

Validation protects rendering and selected identity/version consistency, not authorization, every quote endpoint or guaranteed current stock. Warnings and action blocks are in memory; reload does not guarantee a delayed request has completed. Actual multi-tab concurrency, full screen-reader/device testing, delivery fees, payment and order placement remain outstanding. No Supabase connection, user database change or production deployment was performed.
