# Limited UI browser audit — 2026-11-08

A locally built Next.js app was checked in headless Chromium, with no configured live backend. Sixteen routes were checked at widths of 390 and 1440 CSS pixels: `/`, `/shop`, `/account`, `/cart`, `/checkout`, `/checkout/recipient-preview`, `/vendor`, `/vendor/product-preview`, `/vendor/variants-preview`, `/vendor/inventory`, `/vendor/orders`, `/rider`, `/rider/delivery-preview`, `/admin`, `/admin/review-preview` and `/login`. The basic checks covered successful HTTP responses, document-level horizontal overflow and page errors. Seven routes also passed document-level overflow checks at 320px. These checks exercised unavailable and preview states, not real products, authenticated users or backend data.

Axe Core 4.10.2 scans at 390px reported no automatically detected violations in those default states. At 320px, separate scans found no violations or document overflow in the storefront menu-open, rider pickup/route, rider delivery-proof and admin identity-review states. The scan initially identified insufficient contrast on the shared inverse footer logo; the logo color was adjusted and the scan rerun. Keyboard checks covered opening the storefront menu and focus after adding a temporary vendor option. Additional interactions covered removing/validating preview options and disabled recipient, rider and admin decision controls. A small number of screenshots were visually inspected at mobile and desktop sizes.

This is **not** a complete accessibility, design-fidelity, security or UX sign-off. Automated scans do not cover all WCAG requirements. Screen readers, zoom, localization, browser/device diversity, forms with real data, authorized workflows, product detail with a real catalog, resilience, error recovery and end-to-end operations still need testing. The UX is not production-ready: key checkout, customer, vendor, rider and admin workflows remain unimplemented or unconnected. Layout previews deliberately do not provide those operations.
