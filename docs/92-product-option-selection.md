# Product option selection

Buyers must explicitly choose an orderable product option before adding it to the cart, even when only one option is currently shown. The select lists each available, positively priced option with the catalog's formatted unit price, and the chosen option and price are repeated below it. This avoids silently adding the first option when products have different variants or prices. If a selected option disappears on refresh, it must be selected again even if it returns. The UI explains that prices and availability can change and adding to the cart does not reserve stock. The server remains authoritative for cart eligibility and checkout reservation; no new backend or database behavior is introduced.

Long product titles, breadcrumbs, store names, option names and descriptions can wrap on narrow screens. Unit/component tests use synthetic variants and mock requests; they cover selection, price changes, invalid quantities, disappeared options, duplicate requests and error feedback. Headless Chromium checks with a synthetic local catalog and a mocked cart response exercised selection, displayed price, submitted variant, overflow and Axe scans at 320px, 390px and 1440px. No live login, cart, catalog, real-device or screen-reader testing is claimed. No production deployment or database configuration changed.
