# Disposable database role setup: safe password quoting

`scripts/setup-db-roles.sh` previously interpolated environment variables into a SQL heredoc. Passwords containing quotes could break the statement or inject SQL. It now invokes a small Node/`pg` helper: a parameterized query places the three passwords in transaction-local settings, and a fixed PL/pgSQL block uses PostgreSQL's `%L` literal quoting for the role DDL. All three role changes commit together, and failures attempt rollback. CLI errors are generic; the PL/pgSQL exception handler avoids returning dynamic SQL error context. Empty or NUL-containing passwords fail before connecting. The script still creates/updates `gs_owner`, `gs_runtime`, and `gs_privileged`, and applies `NOBYPASSRLS` to the latter two as before; it is not a role-privilege audit and does not remove other attributes or memberships from existing roles.

**Only use this helper on a confirmed disposable local cluster.** Roles and password changes are cluster-wide, including when the target database is a test database; existing passwords will be replaced. `PGHOST` is restricted to loopback or a Unix socket, and `PGSERVICE`, `PGSERVICEFILE`, and `PGHOSTADDR` are rejected; this reduces accidental remote targeting but is not proof of isolation (a local socket or proxy may reach another server). Node and installed `pg` dependencies are required, in addition to PostgreSQL role-administration privileges. With no `PGHOST`, the helper uses `/var/run/postgresql` for a local Unix socket (unlike node-postgres's TCP default). Existing bootstrap filesystem/OS-user access requirements still apply.

Passwords are not included in CLI arguments, SQL text sent by Node, or normal helper output. They remain present in process environment, PostgreSQL session memory and password-management operations; database statement/parameter/audit logs, debugging, tracing, proxies, server-side errors and privileged access can expose secrets. Use synthetic credentials and restricted logs for tests, and do not run this local bootstrap against hosted or valuable data. Transaction commit failures can have an unknown outcome; inspect the target rather than assuming rollback.

Unit tests exercise special characters, parameterization, validation, remote-target rejection, rollback and generic CLI errors. Separately, a freshly initialized local PostgreSQL 16 cluster with synthetic credentials verified both CREATE and ALTER using quote/backslash/dollar payloads, matching SCRAM verifiers, a surviving SQL-injection sentinel, and an unauthorized attempt leaving previous credentials unchanged. The disposable server was stopped. CI's disposable PostGIS integration setup exercises the ordinary role setup; this is not a hosted Supabase migration, role audit or deployment.
