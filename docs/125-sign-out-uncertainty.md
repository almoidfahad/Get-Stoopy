# Sign-out uncertainty

The web logout route previously discarded every backend error, cleared the browser cookie and redirected home. When a server-side revoke failed or its response was lost, this left no indication that the server session might remain usable. The route also waited indefinitely for a stalled service.

For a same-origin logout with a session cookie, the BFF now waits up to eight seconds and accepts only the API's documented 204 as confirmation. Redirects are not followed. Network failures, timeouts and all other statuses—including 401 and unexpected 2xx—are treated conservatively as unconfirmed. In either outcome the response asks the browser to clear its local session cookie; an unconfirmed outcome redirects to a dedicated noindex warning page. That page does not depend on the account API, so it remains available if the service is down, and explains the distinction between this browser, the server session, the identity provider and other devices. The account form also explains its limited scope. Missing/cross-origin requests remain rejected without clearing cookies or contacting the API.

The local cookie is deliberately cleared even when revocation is unknown, to avoid retaining access in the browser. This means the same browser cannot retry revocation using the removed token. A timed-out request can still finish later, and the warning is not proof that it failed. This does not revoke other devices or the identity-provider session. A missing/invalid web configuration can still prevent the logout route from executing its origin check or cookie deletion.

Verification: 767 unit/component tests, typecheck and an isolated production web build passed; after a wording-only change the focused tests and build passed again. Unit tests exercise confirmed 204, no cookie, unexpected statuses, redirects, network errors, timeout handling, CSRF/origin checks and cookie deletion. At 320, 390 and 1440 CSS pixels Chromium tested keyboard sign-out against a synthetic session API: revocation failure, applied revocation with a lost response, and confirmed revocation; selected Axe and overflow checks passed on the warning. A stalled request timed out, cleared the browser cookie and later completed at the fixture without changing the warning. A 390px JavaScript-disabled check exercised the native form and warning. No real identity provider, live user or database was used.

Real authentication, provider logout, full accessibility/device testing and production deployment remain unverified. No Supabase connection, user database changes or production deployment were made.
