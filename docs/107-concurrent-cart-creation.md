# Concurrent first-cart creation

Creating a buyer's cart first looks up an existing row and then inserts one. Previously, two overlapping requests could both find no cart; the unique constraint prevented duplicate rows but the losing request could fail rather than receive the existing cart. The API now takes a transaction-scoped advisory lock keyed by the normalized buyer and country UUIDs before that lookup. The existing unique constraint remains the final database guard; the lock is coordination, not authorization. Hash collisions can serialize unrelated requests, and a prolonged holder can still cause a transaction timeout. This does not provide idempotency for adding, changing, or removing items.

The integration regression test holds the exact lock, starts two equivalent requests (including an uppercase UUID), checks both are blocked while a different buyer succeeds, then verifies both responses refer to the same cart and only one cart, creation audit and outbox event exist. This requires the repository's isolated PostgreSQL/Redis CI fixture; no user database, migration, or production service is touched. Local typecheck and API build passed; real PostgreSQL integration is pending CI.
