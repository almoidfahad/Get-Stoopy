# Returning to shop results

Shop product links carry the normalized search term, category and current pagination cursor to the product page. A visible “Back to results” link rebuilds the corresponding shop URL; when there are no valid filters it says “Back to shop”. Product-unavailable retry and return links preserve that context. Links from the home page remain ordinary product links. A stale cursor may legitimately return an empty page; the shop already offers a first-page link in that case.

The destination is always constructed from supported catalog fields; arbitrary return URLs are never used. The same normalization and limits as the shop query are applied. This preserves filters, not a snapshot of the results or scroll position. The product-not-found boundary still links to the general shop rather than preserving context. No identity, checkout or backend behavior changed.

Unit and server-rendered tests cover search encoding, category/cursor, invalid/repeated inputs, ignored arbitrary return destinations and unavailable-product retry. A synthetic local catalog was used for keyboard navigation shop → product → shop at 320, 390 and 1440 pixels, checking the URL and selected Axe/overflow results. The synthetic API did not validate actual search results or pagination semantics. Typecheck, web build and 534 tests passed locally. This is not an end-to-end live-catalog, cross-browser, screen-reader or real-device audit; production was not changed.
