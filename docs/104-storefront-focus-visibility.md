# Storefront focus visibility

The catalog card's link is inside a rounded `overflow-hidden` container. The global positive-offset focus outline could be clipped outside that container. The link now draws its keyboard focus outline inside the card. The site-wide and shop search buttons also draw a white inset focus outline on their red backgrounds: previously the enclosing focus ring did not distinguish the button from the input and the button's own outer outline could be clipped.

Component/server-rendered tests cover the relevant classes. With a synthetic catalog in a locally built server, headless Chromium at 320, 390 and 1440 pixels checked keyboard tabbing from each search input to its submit button, actual computed focus styles on both buttons and the product card, document overflow and selected Axe results. A 390px card screenshot was visually inspected for the inset outline. Typecheck, production web build and 543 tests passed. This is a limited keyboard check, not a real-device, screen-reader, high-contrast-mode, cross-browser or full accessibility audit. No live data or deployment was changed. The JavaScript-disabled 404 issue documented in `103-product-card-accessibility-and-404.md` remains unresolved.
