# Recipient layout preview

The project requires buyer and recipient to be separate and the recipient's destination to drive delivery serviceability (`docs/04-geographic-model.md`; UI-H25 in the design inventory). There is no dedicated recipient checkout screenshot, so this is a storefront-consistent interpretation awaiting review. `/checkout/recipient-preview` is a clearly labelled, public **layout preview**, not an implemented checkout flow. It lets the viewer switch between ordering for themselves and someone else, with contact and address fields disabled. The preview never accepts, stores or sends recipient details, does not read account details or request location, and does not reserve stock or place an order. A link is available both when checkout is unavailable and when a quote screen is present.

The existing real quote remains city-only and unchanged. Recipient/address capture, saved addresses, validation, serviceability by address, recipient persistence and order placement still require backend integration; the preview does not supply any of them. No payment or database/production configuration changed. DOM tests cover switching, disabled fields, absence of a submit action and no fetch during interaction; server-rendered tests cover preview links in checkout states. Real-device visual, keyboard and assistive-technology testing are outstanding.
