# Keyboard focus after removing a cart item

After a successful cart removal, the refreshed server-rendered cart may remove the focused button. Keyboard focus could fall to the document body, especially when the last item disappears. The cart page heading is now a programmatic focus target. Immediately after a confirmed successful removal and before refreshing, the client moves focus there only if the user is still focused on that remove button. It does not move focus if the user navigated elsewhere while waiting, and it does not move focus after an error or an uncertain outcome. Existing duplicate-request and uncertain-outcome safeguards are unchanged. A successful response followed by a failed refresh can still leave stale cart content; this change does not make mutations durable or idempotent.

Local checks: 616 unit/component tests, typecheck and an isolated production web build passed. At 320, 390 and 1440 CSS pixels, Chromium with a synthetic cart/session and intercepted delayed deletion checked pending focus, repeat suppression, heading focus after the last item disappears and the empty cart renders, no heading focus theft when the user moves away, uncertain-response focus, selected Axe checks on the empty cart, and document overflow. Component tests cover the same focus conditions and server-rendered tests check the empty-cart heading target. A user moving to another control that itself disappears on refresh may still need separate focus recovery; multi-tab updates and real screen readers remain unverified.

No real cart, identity provider, Supabase or user database was used and no production deployment was made. This limited improvement does not complete checkout, payment, accessibility, or end-to-end testing.
