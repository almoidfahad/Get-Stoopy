# Quote routing identifier safety

The checkout quote-shape validator previously accepted any nonempty strings as quote, cart and destination identifiers. The create-success path checked the cart and city against the attempt but did not validate the new quote ID. A malformed successful response could therefore be shown as a reservation even though the release/read endpoints only accept UUIDs, leaving the buyer with a release control that cannot route to the held quote.

The shared server/client validator now requires UUID-shaped quote, cart and destination identifiers, case-insensitively. Invalid create responses follow the existing uncertain-outcome path, retaining the entire original attempt for an idempotent retry; unreadable recovered quotes and conflict reads use their existing recovery warnings, and invalid release responses stay uncertain. Tests now use realistic UUIDs for responses as well as distinct valid-but-wrong IDs so shape and identity checks are independently exercised.

Local verification: 736 unit/component tests, typecheck and isolated production web build passed. Tests cover invalid identifier types, path-like IDs, newline and malformed UUIDs, case-equivalent IDs, mismatched valid IDs, initial quote recovery, create, conflict reads and release responses. At 320, 390 and 1440 CSS pixels, Chromium used a synthetic API through the local BFF: the first create actually reserved stock but returned a malformed quote ID; the UI retained focus and warned of uncertainty, retried the identical command, adopted the valid response and released it. Selected Axe and overflow checks passed. The fixture implements its own idempotent behavior and is not a real commerce backend.

A UUID-shaped identifier is not proof of ownership, identity, stock or correctness of every quote field. The backend remains responsible for authorization and actual idempotency; the warning is in memory and a reload cannot guarantee an earlier delayed request has finished. Real-service E2E, cross-tab concurrency and full accessibility/device testing remain outstanding. No Supabase connection, user database changes or production deployment were performed.
