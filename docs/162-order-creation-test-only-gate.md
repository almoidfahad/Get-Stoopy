# Block incomplete subtotal-only orders outside tests

The order API could previously create a COD or sandbox-manual order directly from a product-subtotal-only quote even though the storefront hides ordering. That quote has no authoritative delivery charge, tax, total or bound pre-order recipient/destination. A COD policy being enabled is not evidence that customer checkout is complete. Hiding the UI is not a backend enforcement boundary.

`OrdersService.createFromQuote` now rejects both methods with `503 ORDER_CREATION_DISABLED` unless the validated API environment is `test`. The check occurs in the service before any transaction, quote consumption, inventory movement, order, audit or outbox write; it applies to direct API calls and other callers of that service. It also rejects order-create retries outside test, even if an order with the same idempotency key already exists. Existing order reads, cancellations and quote releases are not disabled by this gate, allowing separately authorized recovery. Tests simulate development, staging and production with a valid reserved quote and assert both payment methods are denied, no order created and quote/stock unchanged; existing disposable integration tests continue to exercise order creation and idempotency in test mode.

This is an application boundary, not a database-level prohibition. Direct privileged database writers or a misconfigured deployment using `NODE_ENV=test` can bypass it: test mode must never connect to real data. Quote creation/reservation itself remains available and must be monitored/released or expired; this change does not disable quotes. No customer delivery fee or tax policy is invented. The gate must not be removed merely by setting a feature flag: a future production checkout needs an approved pricing policy, bound encrypted recipient/destination, transactional authoritative serviceability and total, secure identity and key/retention controls, payment/COD readiness, isolation and end-to-end operational verification. Existing database orders and other financial/fulfillment operations are not made safe by this change. No hosted database or deployment was changed.
