# Homepage hero and interactions

The first slide is the user's supplied JPEG, kept byte-for-byte unchanged as `apps/web/public/images/home-slider-cover.jpg` (SHA-256 `0c101411c62468490c17084107a3fe02facc2fdec1696b493876e7044082ff1f`). It is displayed in full rather than cropped. The second slide is an AI-generated warm street-market scene with a shopper, burgundy shopping bags and a delivery scooter, created to complement the store's red, cream and black palette. There are no fabricated offers or product claims in the generated slide.

The interval is controlled by `HERO_AUTOPLAY_INTERVAL_MS` in `apps/web/src/components/home-hero.tsx`. Slides crossfade over one second. On desktop, the shop button and slide dots sit over the lower part of the fitted cover, following the supplied layout reference; on narrow screens they remain below the complete image so controls do not obscure it. Automatic motion requires a desktop-size fine hover pointer and no reduced-motion preference; it pauses on hover, focus, explicit pause or when the tab is hidden. Mobile/touch and reduced-motion visitors can use arrows, dots and horizontal swipes without autoplay. The pause/play control visibly explains when autoplay is unavailable. Manual changes are announced; automatic changes are not repeatedly announced. The supplied first image stays fully visible; a slow zoom is applied only to the generated slide on eligible desktops.

Homepage sections use a small IntersectionObserver enhancement: content remains visible without JS, without the observer, on reduced motion, and on keyboard focus. Subtle card/link hover, button press, confirmed cart feedback and desktop-only cursor glow use CSS and existing React/browser APIs; no animation library was added. A successful cart message still requires a confirmed server result, and uncertain outcomes remain separate. The homepage cards navigate to product details; no unsupported quick-add behavior was introduced.

Checked with unit/interaction tests, typecheck, production web build and local browser testing at 320, 390, 768 and 1440 pixels, including axe, overflow, autoplay/hover, reduced motion, mobile manual controls, section reveal and a JavaScript-disabled page. This does not imply live catalog, authentication, cart, checkout or payment services are configured; no live deployment is part of this change.
