# Supabase development preflight: connection safety

The read-only preflight previously checked the hostname in a PostgreSQL URL but then passed the entire URL to `pg`. The driver lets URL query parameters override separately supplied connection settings: for example, `host` can change the destination, `sslmode=disable` or `sslmode=no-verify` can weaken TLS, and `options` can replace the read-only default. An `sslrootcert` parameter can also cause local file reads and override the supplied CA. This was a tooling defect; there is no evidence it was exercised against the target database.

The preflight now rejects URL query parameters except a single `sslmode=verify-full`, rejects fragments and requires explicit URL user and password. It builds `pg` options directly from the checked URL, sets verified TLS itself, honors the dedicated CA-file setting and explicitly sets the read-only session default and timeout. It does not log connection options or credentials. Tests exercise malicious override attempts and inspect the actual `pg` client's connection parameters with hostile `PGHOST`, `PGSSLMODE` and `PGOPTIONS` defaults. They use synthetic credentials and no connection. Remove unsupported query parameters from a development URL before use; supply a CA via `SUPABASE_DB_CA_CERT_PATH` when needed. TLS verification is never disabled.

All preflight queries remain SELECT-only. The PostgreSQL read-only default is defense in depth, **not** an immutable security boundary: a sufficiently privileged session may change it, and SELECTs can call functions with side effects. Use a suitably restricted role, review the queries and the target, and do not interpret a successful preflight as migration approval. `NODE_ENV=production` still prevents this development tool from running, but the name alone does not prove a target is non-production; independently confirm the intended project and environment. No Supabase connection, migration, role, data, secret or live deployment was changed. Connector access remains unresolved; the earlier 403 is not re-tried here.
