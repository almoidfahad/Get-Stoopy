# Test-only saved-recipient delivery preview

The test-only draft can now be revalidated through `POST /api/v1/commerce/carts/:cartId/recipient-draft/preview`. The endpoint requires an authenticated owner, CSRF/origin, current cart version and draft version. It reads the cart and encrypted draft in one repeatable-read transaction, verifies ownership, versions, expiry and the draft's cart-version binding, decrypts only in memory, and reuses the exact-zone coverage validation from the existing preview. It checks expiry again before returning. The response has `Cache-Control: no-store`, does not include contact, address or coordinates, and explicitly reports `PREVIEW_ONLY`, `quoteBound: false`, `coverageGuaranteed: false`, no stock reservation, no order and null delivery fee/total.

A cleared or expired draft, changed cart, changed draft version, invalid destination or revoked store coverage is rejected. The preview does not write a quote, draft, audit or outbox record. It observes a consistent point-in-time snapshot, not an enduring promise: changes may commit while it is in progress or immediately afterwards. Any later authoritative quote/order must recheck and transactionally bind the recipient and destination to prices, stock and the order; no existing quote is changed here. The endpoint and drafts are hard-disabled outside `NODE_ENV=test`, are not wired to the storefront and must not be used with real customer information.

Disposable PostgreSQL tests cover ownership/CSRF, non-echo/no-write behavior, stale and cleared/expired drafts, coverage suspension and restoration, and a forced interleaving in which the cart changes after the draft is read: the preview returns the old, internally consistent snapshot and a fresh request detects the changed cart. Current encryption, retention, backup, logging, key-management and legal-review limitations from docs 153–154 still apply. No hosted database or deployment was changed.
