# Cart mutation response safety

The web BFF and cart controls previously treated any HTTP 2xx as a completed cart change, even if the upstream or BFF body was missing, unrelated or malformed. This could display an incorrect “Added” message or move focus as if removal succeeded while the actual result was unknown.

After add, update or remove, the BFF now checks the successful upstream response is a structurally valid cart for the same market and cart, has advanced beyond the expected version, and reflects the requested line change. A matching response includes `mutationConfirmed: true` in the BFF response. The browser requires this marker before reporting success, refreshing or moving focus after a removal. A malformed or inconsistent 2xx is mapped to a 502 unknown outcome and the existing uncertainty UX blocks repeat actions and offers recovery. Network errors and explicit 4xx rejections retain their previous handling. This is a consistency check on the returned cart, not proof against a dishonest upstream or a durable mutation command log.

Local verification: 693 unit/component tests, typecheck and an isolated production web build passed. BFF tests cover valid add/update/remove, malformed 2xx responses, wrong identity/market, old versions, wrong line outcomes, preserved 409 errors and the actual route's confirmed/unknown responses. Component tests cover malformed or missing confirmation and focus behavior. Chromium at 320, 390 and 1440 CSS pixels used a synthetic upstream through the real local BFF: the synthetic server applied add/remove but sent malformed 2xx responses; the UI warned instead of claiming success, preserved focus and blocked repeat actions. An explicit acknowledged add with a valid response succeeded. Selected Axe and overflow checks passed. No real user cart, identity service or payment was used.

The block is in-memory, not durable or cross-tab idempotency. Reload and acknowledgement cannot ensure a delayed request has finished and may lead to duplicates. The response contract now includes the confirmation marker; browser and BFF changes must be deployed together. Actual checkout/order/payment and end-to-end verification remain incomplete. No Supabase connection, user database change or production deployment was performed.
